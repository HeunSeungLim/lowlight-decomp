Measurement code and per-frame numbers for the paper.

code/            measurement, reproduction and audit scripts (numpy/torch; see docstrings)
numbers/         per-frame dumps every table and number in the paper is generated from
paper_tables/    the generator that turns numbers/ into the LaTeX rows and prose macros, and
                 the audit that checks every number printed in the compiled PDF against numbers/

Data: Sony sRGB SID in the processed form released with Retinexformer; LOL v1 eval15;
LOL v2 real and synthetic test sets. Weights: the authors' released checkpoints.
Metrics: PSNR/SSIM implemented independently in code/repro_measure.py; agreement with the
authors' implementations and scikit-image is reported in the paper. TF32 was disabled for
the multi-frame comparisons (it moves single-frame PSNR by about 0.004 dB).

## Added baselines (260905)
- code/newbase_{snrnet,llformer,gsad,lightendiff,uretinex,zerodcepp}.py run the released checkpoints (sources and settings in numbers/NEWBASE_*.md) and write float32 CHW RGB [0,1] caches that compare_methods.py reads (repro/cache_<key>/<bench>/<id>.npy).
- cache_lol/ is not tracked here; the 15 LOL-v1 test outputs per method and the Sony caches (598 frames, about 3.4 GB per method) are both regenerated by the same scripts, and `$LLCACHE` points at wherever they are written.
- Third-party repositories are expected under third_party/<name> at the release root (set RETINEXFORMER_REPO for the Retinexformer clone).

## Paths
- Run every script from the release root: repro dumps are read from numbers/, paper tables from paper_tables/, third-party repos from third_party/ at the release root (scripts resolve `third_party/<name>` relative to the working directory).

## Measurement code for the correction and its controls (260909)

code/method_260909/    the highlight-anchored correction, its controls and the diagnostics behind them
numbers/method_260909/ every JSON the paper's final-section numbers are generated from, with run logs

Key entries. `final_rule.py` applies the rule at q=99.9 to four Sony models and six LOL models with
scene bootstrap and Holm adjustment. `controls_v58.py` fits the oracle constant on the acting frames,
permutes the multipliers across those frames, and pairs the two by scene. `affine_oracle.py` fits the
whole-frame affine colour map that contains the global and per-channel gains. `concentration.py`
reports how the pooled gain falls when the best scenes are removed. `exposure_frame_means.py`,
`precond_transfer.py`, `qsweep_rule.py`, `robust_acting.py` and `shares.py` produce the remaining
final-section dumps. `tost_equivalence.json` records the equivalence resolution the paired comparison
supports.

Paths. Scripts read the benchmark under `$LLDATA` (default `data`, and the layout below it is the one
Retinexformer's release uses: `lowlight_model/data/...` and `lowlight_model/weights/...`), the cached model
outputs under `$LLCACHE` (default `cache`), a third-party clone under `$RETINEXFORMER_REPO` (default
`third_party/Retinexformer`), and the receipts they write and read under `$LLMETHOD` (default
`numbers/method_260909`). Every path a script resolves is either one of those variables or relative to the
script itself. The figure generators additionally need `$LLDATA` and `$LLCACHE` set, because they read the
benchmark frames they draw. `cache_lol/` is not tracked here because the six LOL caches regenerate from
`code/newbase_*.py` in a few minutes each, and the intermediate `.npz` feature and control caches are
not tracked either: each is rebuilt by the script that names it, from the benchmark and the model
caches above.

Layout of this section. `code/method_260909/` holds the scripts, `numbers/method_260909/` the JSON
receipts and the `.log` transcript of the run that produced each one, so a receipt can be read without
rerunning anything.

Audit and manuscript. `paper_tables/` carries the compiled `main.pdf` together with the sources that
build it, so the audit runs with no further inputs:

    python paper_tables/audit_paper_numbers.py

It extracts every number printed in the PDF and matches it against the receipts, and reports how wide
its own acceptance windows are, so a reader can judge how much a match is worth. Beyond that pool check it
re-runs the five generators in a copy and compares, with no tolerance, every macro the manuscript uses and
every generated table row, so a printed number that is not a function of a receipt fails; it verifies the
dump hash a receipt records, so editing a dump and its printed value together fails; and a missing receipt
or a generator that cannot run is a failure rather than a skip. It does not check that a generator computes
the right thing — only that what is printed is what the generators produce from the receipts. `paper_tables/_isolation_test.py` is the stricter check the frozen review
bundle ships with, where every receipt sits beside the audit in one directory; run in this release it
reports the receipts it reaches through `numbers/`, which is the layout documented above, so it is the
bundle's test and not this release's. Rebuilding the PDF needs `pdflatex` and `bibtex` and nothing else:

    cd paper_tables && pdflatex main && bibtex main && pdflatex main && pdflatex main

Audit. `paper_tables/audit_paper_numbers.py` extracts every number printed in the compiled PDF and
matches it against these dumps. It separates values matched against measurement dumps from values that
match only a generated LaTeX file, and reports the second count, because a printed value cross-checked
against its own generated copy is not independently verified.

## Environment variables

    LLDATA   benchmark root (Sony SID and LOL live under it)
    LLCACHE  cached model outputs; default numbers/cache_retinexformer_sony
    LLROOT   this repository root, for scripts that read numbers/ by absolute path

Scripts under `code/method_260909/` read the per-frame dumps in `numbers/` and the caches under
`$LLCACHE`. Set `LLROOT` to this directory before running them; the dumps a script expects are
named in its docstring.
